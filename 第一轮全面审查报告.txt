 Dragon Pulse Plus 全面审查报告

  一、严重 Bug (会导致程序异常或决策错误)

  Bug 1: LLM 备用模型永远不会触发 (llm/client.py:86-88)

  generate() 方法在 retry 循环内 raise e 后，备用模型代码（第88行之后）永远执行不到：

  # 第86行：最后一次重试失败直接 raise，函数退出
  raise e
  # 第88行之后的备用模型代码是死代码

  修复方案：用 try/except 包住整个重试循环，将 raise 改为 break 或 catch 后走 fallback。

  ---
  Bug 2: 卖出信号的跌停判断使用了错误股票的涨跌幅 (market_monitor.py:819)

  # 第819行
  if MarketMonitor._is_limit_down(code, change_pct):

  此处的 change_pct 变量在 for holding in active_holdings 循环中从未定义。它引用的是上方 for _, row in hit_df.head(5).iterrows() 循环中最后一只异动股的涨跌幅——完全是另一只股票的数据。如果异动扫描为空（hit_df.empty），则 change_pct 会引发 NameError。

  修复：在第762行附近提取正确的变量：
  curr_change_pct = float(row["change_pct"])
  然后第819行使用 curr_change_pct。

  ---
  Bug 3: was_limit_up_today 字段从不重置 (无清理逻辑)

  数据库中的 was_limit_up_today 一旦设为 True，没有任何代码在新交易日将其重置为 False。隔夜持仓的股票第二天开盘会被误认为"今日曾封涨停"，错误触发"断板必卖"信号。

  修复：在 _reset_daily_state() 中添加全表重置：
  HoldingManager.reset_all_limit_up_flags()

  ---
  Bug 4: 推荐标的永远不过期，盘中监控会买入历史推荐 (daily_runner.py + market_monitor.py:508)

  - 盘后复盘保存推荐时 trade_date = today_str（当天日期）
  - 竞价观察时用 trade_date=today_str（次日日期）→ 查不到昨天的推荐
  - 但盘中监控 get_pending_recommendations() 无日期过滤，返回所有历史 PENDING 推荐

  这意味着几周前的失效推荐会一直被当成有效买入标的。

  修复：
  1. 盘后推荐的 trade_date 应该设为次日交易日
  2. 盘中监控加上日期过滤：只看今天的推荐
  3. 增加过期逻辑：前一交易日的 PENDING → EXPIRED

  ---
  Bug 5: 涨停判断未区分20cm股票 (market_monitor.py:764)

  is_zt = float(row["change_pct"]) >= 9.8  # 对所有股票都用9.8%

  创业板(300/301)和科创板(688)的涨停是20%。涨幅+15%的创业板股票不会被标记为封板，导致 was_limit_up_today 设置错误，进而"断板必卖"规则对20cm股票完全失效。

  ---
  二、计算逻辑缺陷

  问题 6: 情绪指数 score_breadth 存在系统性偏空 (emotion_index.py:72)

  score_breadth = max(min((breadth + 30) * 1.25, 100), 0)

  - breadth=0（涨停=跌停，中性市场）→ score = 37.5（远低于中位数50）
  - breadth=50 → score=100
  - breadth=-30 → score=0

  问题：中性市场下情绪分就已被压低，导致系统整体偏空。建议改为：
  score_breadth = max(min((breadth + 40) * 1.0, 100), 0)  # 中性时=40，更合理

  ---
  问题 7: score_support 计算使"承接维度"权重减半 (emotion_index.py:111)

  score_support = max(100 - zhaban_rate * 2, 20) * 0.5  # 范围 [10, 50]

  由于乘以0.5后值域为[10,50]而非[0,100]，实际对总分的贡献只有 50*0.15=7.5 分（最大），而非配置的15%权重。这让"承接"维度的影响力被隐性削弱了一半。

  ---
  问题 8: 午间休市期间成交额预估偏高 (fetcher.py:227-281)

  estimate_today_amount() 在11:30-13:00午休期间计算错误：

  - 12:00时刻：minutes_elapsed = 150-90 = 60 → ratio≈0.45
  - 但实际上午盘已结束，真实比例应为0.60
  - 导致全天成交额被高估约33%（now/0.45 vs now/0.60）

  这使午休期间容量因子K被虚高，可能导致系统误判为"增量市场"而采用过于激进的策略。

  修复：午休期间直接使用0.60作为ratio：
  if 11*60+30 < current_minutes < 13*60:
      ratio = 0.60  # 上午成交占全天60%

  ---
  问题 9: 盘后与盘中情绪公式权重不一致

  ┌──────────┬─────────────────┬──────────────────────────────────┐
  │   维度   │ 盘后calculate() │ 盘中compute_intraday_sentiment() │
  ├──────────┼─────────────────┼──────────────────────────────────┤
  │ 溢价     │ 25%             │ 40%                              │
  ├──────────┼─────────────────┼──────────────────────────────────┤
  │ 宽度     │ 20%             │ 25%                              │
  ├──────────┼─────────────────┼──────────────────────────────────┤
  │ 高度     │ 15%             │ 20%                              │
  ├──────────┼─────────────────┼──────────────────────────────────┤
  │ 承接     │ 10%             │ 15%                              │
  ├──────────┼─────────────────┼──────────────────────────────────┤
  │ 力度     │ 10%             │ —                                │
  ├──────────┼─────────────────┼──────────────────────────────────┤
  │ 破规胆量 │ 20%             │ —                                │
  └──────────┴─────────────────┴──────────────────────────────────┘

  盘中缺少"力度"和"破规胆量"两个维度可以理解，但溢价权重从25%跳到40%意味着同样的市场在盘中和盘后会得到明显不同的情绪分。盘后推荐基于一套分，盘中执行基于另一套分，可能产生策略冲突。

  ---
  问题 10: 市场风格分类存在覆盖漏洞 (strategies.py)

  当 height=4, zt_count=80, sentiment_index=60 时：
  - 优先级2（共振）：需 zt_count >= zt_dip_min(≈40) 且 sentiment_index >= 55 ✓ → 实际上会被共振捕获

  但 height=4, zt_count=35, sentiment_index=55 时：
  - 优先级2（共振）：zt_count < zt_dip_min(40) ✗
  - 优先级3（打板）：height < 5 ✗
  - 优先级4（低吸）：zt_count < zt_dip_min(40) ✗
  - 优先级5 高标补充：height < 5 ✗
  - 最终 → 观望

  这种"涨停35家+情绪55分+最高4板"其实是典型的修复期初段（适合低吸2进3），但被归为"观望"。

  ---
  问题 11: Core Pool Beta 相关性过滤形同虚设 (core_pool.py:77)

  beta = 0.85  # 默认值
  if board_index_series is not None:  # 几乎永远为 None
      ...

  整个项目中没有任何调用方提供 board_index_series 参数。Beta 永远是 0.85（硬编码），声称的"皮尔逊相关系数>=0.8过滤"完全不起作用。

  ---
  问题 12: 昨日推荐评估用日历日而非交易日 (daily_runner.py:407)

  yesterday = (datetime.datetime.strptime(trade_date, "%Y%m%d") -
               datetime.timedelta(days=1)).strftime("%Y%m%d")

  周一执行时 yesterday=周日，查不到任何推荐。应使用交易日历获取前一交易日。

  ---
  三、系统设计不完善之处

  问题 13: 无仓位管理和资金控制

  - AI自动买入永远 quantity=100（1手），无仓位比例控制
  - 无最大持仓数量限制（理论上可同时持有数十只）
  - 无单日最大买入次数限制
  - 无总亏损安全阀（如当日AI交易总亏损>5%时停止）

  建议：增加 MAX_AI_POSITIONS=5, MAX_DAILY_BUYS=3, DAILY_LOSS_CIRCUIT_BREAKER=-5.0 等配置。

  ---
  问题 14: 无绝对止损机制

  当前止损条件：
  - 断板必卖（需要先封板再炸板）
  - 破位止损（跌破VWAP+MA5）

  缺失：
  - 绝对亏损止损（如 -7% 无条件止损）
  - 时间止损（持仓超过3天不涨则离场）
  - 大盘系统性风险止损（如大盘跌>3%时全部清仓）

  对于短线系统，快速止损是核心。建议增加：
  if profit_pct <= -7.0:  # 绝对止损
      signals.append({"type": "绝对止损", "level": "CRITICAL", ...})

  ---
  问题 15: 自动买入无确认价格验证

  系统在检测到信号时直接以实时价格买入，但：
  - 15秒延迟内价格可能已大幅变化
  - 没有验证买入价是否已达涨停（无法成交）
  - 没有滑点预估
  - 一字板判断虽有，但对"T字板"（开盘涨停后打开再封）等场景未覆盖

  ---
  问题 16: 多线程下SQLite并发写入风险

  APScheduler后台任务、FastAPI线程、主线程Monitor 三个写入方同时使用 pool_size=1, max_overflow=3 的SQLite连接池。虽然有WAL+busy_timeout=5000ms，但15:30盘后复盘（大量写入）期间如果API同时被调用，仍可能出现锁超时。

  建议：将写入操作排队，或使用 threading.Lock 保护关键写入路径。

  ---
  问题 17: 缺少"涨停封单衰减"监控

  当前只监控"炸板"（涨停→不涨停），但不监控封单金额衰减。实战中，封单从5亿缩到5000万虽然没炸板，但已经预示大概率要炸。建议增加封单比例变化率的监控。

  ---
  问题 18: 缺少板块联动/跟风监控

  系统对个股异动有监控，但缺少：
  - 板块第一只涨停后，板块内后续跟风标的的监控
  - 板块涨停家数从峰值开始衰减的"退潮"信号
  - 板块间轮动切换的实时监测

  这些对短线情绪交易至关重要。

  ---
  问题 19: 动态权重配置缺乏约束验证 (settings.py)

  PREMIUM_WEIGHT: float = 0.40
  BREADTH_WEIGHT: float = 0.25
  HEIGHT_WEIGHT: float = 0.20
  SUPPORT_WEIGHT: float = 0.15

  无验证：PREMIUM_WEIGHT + BREADTH_WEIGHT + HEIGHT_WEIGHT + SUPPORT_WEIGHT == 1.0。用户可能配置成总和 0.8 或 1.3，导致情绪分范围异常。

  ---
  问题 20: 缺少情绪周期转换规则

  系统有情绪分和风格判定，但缺少跨日的周期状态机：

  冰点 → 启动 → 发酵 → 高潮 → 退潮 → 冰点

  当前每次判定都是独立的，不参考前一日的状态。实际操作中，从"退潮"转"启动"需要明确的触发条件（如连续2日溢价回正+涨停回升），而不仅仅是当前快照符合某一档位。
